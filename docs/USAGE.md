# Usage Guide

This document complements the top-level [README](README.md) with deeper
guidance on common scenarios.

## Spring Boot Integration

If your project uses Spring Boot's built-in Liquibase support, just add the
connector dependency — Spring Boot will pick up `YashanDbDatabase` through
SPI automatically.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
<dependency>
    <groupId>org.liquibase</groupId>
    <artifactId>liquibase-core</artifactId>
</dependency>
<dependency>
    <groupId>com.yashandb.jdbc</groupId>
    <artifactId>yashandb-jdbc</artifactId>
    <version>1.9.24</version>
</dependency>
<dependency>
    <groupId>com.yashandb</groupId>
    <artifactId>liquibase-yashandb</artifactId>
    <version>1.0.0</version>
</dependency>
```

`application.yml`:

```yaml
spring:
  datasource:
    driver-class-name: com.yashandb.jdbc.Driver
    url: jdbc:yasdb://127.0.0.1:1688
    username: sys
    password: ${DB_PASSWORD}
  liquibase:
    change-log: classpath:db/changelog/db.changelog-master.xml
```

## Using with the `liquibase` CLI

Add the connector JAR to the Liquibase CLI classpath:

```bash
liquibase \
    --classpath=liquibase-yashandb-1.0.0.jar:yashandb-jdbc-1.9.24.jar \
    --changeLogFile=db/changelog/db.changelog-master.xml \
    --url=jdbc:yasdb://127.0.0.1:1688 \
    --username=sys --password=your_password \
    update
```

## Generating a Snapshot

```bash
liquibase --url=jdbc:yasdb://127.0.0.1:1688 \
          --username=sys --password=your_password \
          --classpath=liquibase-yashandb-1.0.0.jar:yashandb-jdbc-1.9.24.jar \
          snapshot --snapshotFormat=json
```

The `YashanDbTableSnapshotGenerator` automatically filters YashanDB system
dictionaries (`OBJ$`, `COL$`, `TAB$`, `BIN$…`, `WRH$_…`, etc.), so the
resulting JSON only contains user tables.

## Supported Change Types

Because YashanDB's DDL dialect closely matches Oracle, most standard Liquibase
change types work as-is. A few notable overrides in this connector:

| Change type           | Generated SQL (YashanDB)                                       |
|-----------------------|----------------------------------------------------------------|
| `addNotNullConstraint`| `ALTER TABLE t MODIFY col NOT NULL`                            |
| `dropNotNullConstraint`| `ALTER TABLE t MODIFY col NULL`                              |
| `modifyDataType`      | `ALTER TABLE t MODIFY col <newType>`                           |
| Auto-increment column | `col INT GENERATED BY DEFAULT AS IDENTITY` (v23.4.2+)          |

## Disabling View Snapshots

The connector ships with `YashanDbIgnoreViewSnapshotGenerator`, which disables
view enumeration. This keeps snapshots focused on tables and is helpful when
the YashanDB instance contains many system views.

If you need view snapshots, provide your own `ViewSnapshotGenerator` subclass
with a higher priority than `YashanDbIgnoreViewSnapshotGenerator`.

## Troubleshooting

### Liquibase picks a different `Database` implementation

Make sure:

- The connector JAR is on the classpath.
- `YashanDbDatabase` is listed in `META-INF/services/liquibase.database.Database`
  inside the JAR (inspect with `jar tf liquibase-yashandb-1.0.0.jar`).
- The JDBC product name returned by your driver contains `yashan` (case-insensitive).

### `YAS-04115 "SLICE|MCOL" expected`

This error typically means Liquibase emitted ANSI SQL like
`ALTER TABLE … ALTER COLUMN … TYPE …`. Upgrade to the latest connector version,
which overrides the `ModifyDataType` and `SetNullable` generators to use
Oracle-style `MODIFY` syntax.

### `DATABASECHANGELOGLOCK` is still visible in snapshots

That's expected. `YashanDbDatabase.isSystemObject()` never hides Liquibase's
own tracking tables, even if they live under a schema that would otherwise be
considered "system".
